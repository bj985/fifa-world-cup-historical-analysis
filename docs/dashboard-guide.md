# Dashboard publishing guide

[Project overview](../README.md) · [Methodology](methodology.md)

Use this checklist before publishing dashboard screenshots or the public Power BI link.

## Final dashboard capture

Recommended screenshots:

1. Overall World Cup historical overview
2. Tournament scale, goals and attendance trends
3. Nation performance and title history
4. African nations analysis
5. Match-level or awards analysis
6. 2026 scenario / extension page, clearly labelled

## Keep historical and 2026 content distinct

Historical analysis and the 2026 project extension should not be presented as though they have identical evidence status.

If 2026 rows are simulated, scenario-based, projected or manually supplied, label that directly in the dashboard and README.

## Screenshot quality

- Use readable labels at GitHub width.
- Crop unnecessary application chrome.
- Keep consistent aspect ratios where possible.
- Avoid screenshots containing temporary licence warnings or unfinished visuals.
- Add short captions explaining what question each visual answers.

## Public Power BI link

Before adding a public dashboard URL:

- test it while signed out;
- confirm no private or restricted data is exposed;
- confirm slicers and navigation work;
- verify 2026 labels are unambiguous;
- confirm the published version matches the screenshots.

## Presentation order

Question → data → preparation → SQL → dashboard → interpretation → limitations.
